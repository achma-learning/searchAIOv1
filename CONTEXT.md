## 1. What This Is (Plain English)
- **In one sentence:** a one-page website where a medical student types a topic, gets real research papers back, saves the useful ones with personal notes, and exports them as a reference list.
- **Why it exists:** to make the literature-search part of writing a medical thesis less painful — search, shortlist, take notes, export citations, all in one place, plus a short guide on how to build a focused research question (PICO).
- **Who uses it:** you, and probably fellow med students. It's public on the web, but there are no accounts and nothing is stored on a server.
- **Vibe:** polished personal tool, generated by an AI site builder (Chantan). Looks finished; the code underneath is mostly one big page file.

What a visitor can actually do (`src/pages/Index.tsx`):
1. **Literature search** — type a query, get up to 25 papers from Europe PMC, filter by year and study type, open a paper to read its abstract and copy a citation.
2. **Saved papers** — bookmark papers, add a note to each, export the list as BibTeX or CSV. Saved only in that browser.
3. **Research guide** — static how-to content (PICO, review routine) with a "try this example" button.

## 2. How To Run It
- **Setup once:** install Node.js (22 works; CI uses 22), then in the project folder run `npm install`.
- **Run dev:** `npm run dev` → open http://localhost:5173
- **Build (plain):** `npm run build` → output in `dist/`. Built for the domain root (`/`).
- **Build for GitHub Pages (local test):**
  ```bash
  PAGES_BASE=/searchAIOv1/ npx vite build --config vite.config.pages.ts
  npx vite preview --config vite.config.pages.ts   # → http://localhost:4173/searchAIOv1/
  ```
- **Deploy:**
  - **GitHub Pages:** automatic. Every push to `main` runs `.github/workflows/deploy-pages.yml` and publishes to `https://achma-learning.github.io/searchAIOv1/`. One-time setup: repo **Settings → Pages → Source = "GitHub Actions"**. Can also be run by hand from the Actions tab.
  - **Chantan:** press **Publish** inside Chantan → `https://searchaio-temp.chantan.one/` (link from `README.md`).
- **Required env vars:** none for the current app. `.env.example` lists `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` — Chantan template leftovers; nothing in `src/` reads them.

## 5. Rules For Editing This Code
- **Know who owns the file before you edit it.** If it's listed in `.chantan/pushed-files.json`, Chantan will overwrite your edit on its next sync (`README.md`: "One-way sync"). Either make the change in Chantan, or put it in a new file Chantan doesn't know about.
- **Never put GitHub Pages fixes in Chantan-owned files** (`vite.config.ts`, `App.tsx`, `index.html`, `package.json`…). They go in `vite.config.pages.ts` or the workflow.
- **Use `@/` imports** for anything under `src/` (alias set in `vite.config.ts` and `tsconfig*.json`).
- **Public files are referenced with root paths** like `/assets/x.webp` — that's fine; the Pages build rewrites them. Only top-level names that exist in `public/` or `chantan-assets.json` get rewritten.
- **New routes:** add them above the `*` catch-all in `src/App.tsx` (comment in the file says so). Keep using `<BrowserRouter>` exactly like that — the Pages build looks for that literal tag.
- **User data stays in the browser.** Saved papers/notes use localStorage key `thesis-evidence-saved-v1`. Changing the shape of `SavedPaper` without a migration silently wipes or breaks people's lists.
- **Not medical advice.** The footer says so; keep that framing in any new copy.
- **Don't add a lockfile** unless you also stop syncing from Chantan.

## 6. Fragile Bits & Landmines
- **Chantan overwrites its files.** Original symptom: any edit to a Chantan-owned file just vanishes after the next Chantan push. Fix: our additions live in separate files (`vite.config.pages.ts`, `chantan-tagger.d.mts`, `.github/`, `CONTEXT.md`).
- **`npm run build` used to fail** with `TS7016: Could not find a declaration file for module './chantan-tagger.mjs'` because `tsconfig.node.json` is strict. Fixed by `chantan-tagger.d.mts`. Don't delete it.
- **GitHub Pages sub-path (`/searchAIOv1/`).** Without `vite.config.pages.ts`:
  - the router doesn't match `/searchAIOv1/` → every visit shows the NotFound page;
  - `<img src="/assets/…">` points to `achma-learning.github.io/assets/…` → 404.
  The config fixes both with plain text rewrites at build time, and **fails the build on purpose** if it can't find `<BrowserRouter>` to patch (`vite.config.pages.ts`, `buildEnd`). If Chantan ever switches to `createBrowserRouter`/`HashRouter`, update that plugin.
- **Images aren't in the repo.** `public/assets/*.webp` are downloaded from cdn.chantan.one at build time (`buildStart` in `vite.config.pages.ts`, 3 retries). If that CDN goes away, the Pages build fails. Local builds leave the downloaded files in `public/assets/` (untracked) — don't commit them unless you mean to.
- **No lockfile = unpinned versions.** CI runs `npm install`, so every deploy may pick up newer minor versions within the `^` ranges. Accepted trade-off because Chantan rewrites `package.json`.
- **`chantan-reveal.js` script tag in `index.html`** — the comment there says keep it exactly in place and never inline a reveal script. Platform runtime with a "fail-open" design; leave it alone.
- **`chantan-console.js` / `chantan-selector.js`** ship to production too. They do nothing unless the page is inside Chantan's editor iframe (they check `window.parent`). Harmless; removing them breaks Chantan's editor.
- **Search errors** fall back to showing PubMed / Scholar / Cochrane / CISMeF links (`sourceLinks`). Europe PMC is called with `pageSize=25` and no pagination — you only ever get the first 25 hits.
- **`normalizePaper` uses `any`** for the Europe PMC record. Field names (`authorString`, `pubYear`, `pubTypeList`, `isOpenAccess`) come straight from Europe PMC's `resultType=core` JSON; check their docs before renaming.
- **Filters only apply to the 25 already-fetched results**, not to the API query. "0 match" often just means the filter hid them.
- **README conflicts with reality:** it calls the repo `my-chantan-app (private)` and says "Live site: not published yet", while also linking a live URL. The repo is actually `achma-learning/searchAIOv1`. README is Chantan-generated, so fixing it here won't stick.
- **Large bundle warning (~515 kB JS)** during build — expected, comes from the preinstalled libraries. Not an error.
